## 数量与边界

| 项 | 值 |
|-|-|
| Persona 类别 | 2-3 类，最多 3 类（多角色产品的另一侧占其中一个名额） |
| 行为轴 | 2-3 条 |
| 每个 Persona 内容量 | ≤350 字，任何一条 ≤2 行，典型行为 2-3 条，痛点 2 条 |
| 共同核心题 | 6 道，各候选逐字相同 |
| 候选专属题 | 每候选 4-9 道，各不相同 |
| 每候选合计 | 10-15 题（只问核心题时是 6 道） |
| 访谈份数 | 每类 1 份，共 2-3 份 |
| 需求池 | 发散 6-10 条 → 收口 3-5 条（默认 4） |
| 候选功能 | 总数 5-8 个 |
| 不做清单 | ≥1 项 |
| 报告 | 10 页左右，浮动一两页 |

## 顺序不可颠倒

```
需求池 → 候选功能 → KANO → 设计方向
```

KANO 只筛功能，不筛需求，也不筛方向。

## D/B 与 KANO 的判定边界

- experience goals 与 life goals 只帮助发现可能遗漏的需求，**不直接等于成长性需求或魅力型功能**；“省心、不焦虑、少冲突”也可能对应安全或归属需求。
- D/B 按每条需求缺失时的后果、用户付出与付费侧逻辑逐条判断；KANO 再按「缺失时不满 / 有则更好 / 有则惊喜」逐项判断，不由 D/B 或目标层级直接决定。

## 三个闸门

| 闸门 | 位置 | 定什么 | 可逆 |
|-|-|-|-|
| ① | S1 之后 | 每个候选问完整清单还是仅 6 道共同核心题 | 可逆 |
| ② | S3 校准之后 | 主 Persona（模拟路径是待验证的主 Persona 假设） | 定选后进主线 |
| ③ | S6 之后 | 逐项自检，不通过退回对应回合 | — |

三个闸门都**优先用可点选卡片**（Factory 的 AskUser、Codex / Workbuddy 的等价选择卡片），不可用时退回编号文本。每个闸门 2-4 个选项，每项写清"选它意味着什么"，留"我自己写"的出口。

闸门③ 退回映射：目标偏移 → S1；主 Persona 用错 → S3 闸门②；需求不对 → S4；功能混回 → S5。

## 容易记错的五件事

1. **S1 不定主 Persona。** S1-S2 一律叫「候选 Persona」，主 Persona 在闸门② 才定。
2. **S1 到 S3 不写任何设计启示、产品机会、功能建议。** 画像只描述用户是谁、怎么做事。
3. **记录必须由学生粘回主会话。** 独立对话之间不共享上下文，主会话看不到访谈内容；没收到记录不得进入 S3。
4. **模拟 ≠ 验证。** 模拟路径下 S3 叫「内部一致性校准」，闸门② 定出「待验证的主 Persona 假设」，引用称「模拟回答」而不是「用户原话」。
5. **没问到 ≠ 不成立。** 校准时按三状态处理：支持（替换）/ 反驳（删除）/ 本轮未覆盖（保留并标回假设）。

## 比较主 Persona 时只比什么

只比 **6 道共同核心题的逐项结果**（支持 / 反驳 / 未覆盖）。

不比：证据条数（偏向问得多的候选）、命中率（各题覆盖面不同，4/6 不必然强于 5/14）、专属题的发现（各候选不同，不可比）。

题数与追问次数如实写出，但只用来说明证据厚度，不作为比较指标。

## 交给访谈侧的内容

《访谈身份交接包》只含四项：

```
中性候选代号（A / B / C）
基本背景
核心场景
逐题访谈说明（不含题目与题数）
```

**不给**：行为、动机、痛点、期待、Persona 名称、行为轴位置、分类标签、题目、题数、追问指引。完整问题清单只交给学生，学生逐题提问。

候选之间靠**背景与场景的客观差异**区分（角色、组织位置、是否自己付钱、场景由谁发起、结果交给谁），不靠行为描述。两个候选的背景场景写完几乎一样，说明该回 S1 合并。

## 证据分级

```
事实（真实用户原话 / 后台数据 / 二手真实材料）
  > 模拟回答
  > 推断
  > 常识
```

逐条标来源。模拟回答不是事实。
