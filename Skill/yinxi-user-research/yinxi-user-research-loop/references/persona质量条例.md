# Persona 质量条例

S1 生成候选 Persona、S3 输出修正后的画像之前，都按本条例在后台检查一遍。S1、S3 的说明文件只写本步特有的要求，标准以本文件为准。

## 一、适用范围与运行方式

- 适用于 S1 生成候选 Persona 和 S3 校准后的画像。
- **检查在后台完成。** 用户看到的第一版就是已经检查过的版本。不展示检查过程、检查表或修改前的草稿。
- 发现问题时**逐条修正**，不整版重新生成。修不好的内容在画像中直接标「待补证」，同时写进研究缺口。
- 用户主动询问时，再展示检查表。
- 画像末尾固定加一句声明：「已通过结构与来源检查，不代表已被证实；准确性以 S3 访谈记录为准。」

## 二、四个质量维度

### 1. 典型性：画像代表一类人，不是个例

- 一个画像集中了一类用户的共同特点，不要求特点写得多。350 字的篇幅上限不变。
- 只有一位受访者支撑时，标「单一样本」。
- 行为要写到具体的动作和场景。"重视学习"这种写法不合格。
- 画像内部要一致。如果写了内在矛盾，必须有材料支撑。
- 由多个原型合并成一个画像时，每一条内容都要对每个原型成立。只对部分原型成立的，要注明适用于谁。

### 2. 差异性：候选之间确实不同

- 任意两个候选，至少在一条分群轴上位置明显不同。
- 这个差异必须会影响与业务目标相关的判断。
- 分群轴位置不用单独成栏，但每条轴上的位置都必须能在「用户特点」里找到对应的一条（写法见第七节）。

### 3. 契合性：符合这个产品的真实情况

- 场景是真实的产品使用情境。
- 角色关系符合产品结构，例如谁使用、谁付费、谁验收。
- 产品事实要么已经确认，要么来自官方公开信息。
- 契合性只描述"这个人在这个产品里怎么做事"，不描述"产品该怎么改"。S1 到 S3 不给设计建议。

### 4. 有效性：能支撑本阶段的决策

- 每条分群轴和每条关键行为，都能关联到业务目标。
- 定选和比较必须从记录推出，不能用后面的设计反过来论证。
- 出现"选他，设计才有落点"这类论证，判为不通过。

## 三、两条底线

### 1. 来源可追溯

- 每条关键结论都标注来源类型：事实、模拟回答、推断或常识。
- S3 要**逐条回指到记录编号**，不能按字段笼统汇总。
- 以下三类内容不能标为"事实"，要如实标明来源：
  - 家长转述；
  - 使用者确认；
  - 说话人不确定的内容。

  这条规则要求的是写清证据来自哪里，不是说这类证据弱。来源标对了，转述就是合格的访谈证据。
- 只来自一次观察的结论，要注明强度限制。

**证据要求以研究方法为准。** 判断证据够不够，看这种研究方法能拿到什么，不按理想证据来要求。例如访谈得到的启动方式、动机和习惯，本来就只能来自用户或家长的表达。只要描述具体、前后一致、来源标对，就判为通过，不因为"没有亲眼观察"而判为待补证。

### 2. 缺口可追踪

- 每条关键假设都写明验证途径：在哪一轮、用什么方式验证。

## 四、分群维度规则

- 分群维度有五类：社会属性（性别、年龄、地域、年级等）、功能属性、使用程度、情绪系统、生活观。由业务目标决定选用哪几类。
- 每条分群轴都要说明它和业务目标的关系。分群轴总数为 2–3 条，候选上限为 3 类。
- **社会属性**有三种用法，必须在 S1 声明是哪一种：
  1. 用于划定研究范围；
  2. 作为行为差异的代理，并写出行为链，例如"低年级 → 家长陪学 → 家长验收"；
  3. 被排除。

  社会属性不能单独作为分群轴。
- 定选理由或画像差异中出现、但 S1 没有声明的人口属性，判为不通过。如果已经声明为排除变量，但后来实际参与了定选，判为待补证，要补写行为链。
- 情绪系统和生活观必须有能观察到的行为证据。没有证据的，只能标「假设」。
- 已经用作分群轴的维度，不再在画像里重复写成别的字段。例如用生活观分群时，life goals 要和轴上的位置一致。

## 五、目标层级按需填写

| 层级 | 要求 |
|---|---|
| end goals | 必写 |
| experience goals | 默认要写 |
| life goals | 只在影响本轮业务判断时写，例如影响付费、续费、长期坚持，或构成否决理由 |

没写的层级，要区分两种情况：

- **「本轮未覆盖」**：和业务目标有关，但缺少证据。写进研究缺口。
- **「与本轮业务目标关联弱，不展开」**：附一句理由。不写进研究缺口。

写出的每一层都要通过**套话检验**：如果同一句话放到其他候选身上也成立，就是套话，要重写。

## 六、判定与处理

### 1. 三种结论

每一项只有三种结论。不打总分，也不加权。

| 结论 | 定义 | 例子 |
|---|---|---|
| **通过** | 写法合规，证据达到这种研究方法能拿到的水平，来源标对 | 家长具体描述了孩子怎么开始练，标为「家长转述」 |
| **待补证** | 写法没错，但这个证据访谈本来能拿到，这次没拿到 | 没有正面问启动方式，结论是推断出来的；家长回答含糊或前后矛盾；可以直接问续费意愿，但没问 |
| **不通过** | 画像里写了，但写错了、没有依据，或推导方向反了 | 把转述标成事实；记录里有反证；合并后的内容只对部分原型成立；用设计倒推定选 |

访谈没问到、也没写进画像的内容，标「本轮未覆盖」，写进研究缺口，**不算不通过**。只有把没问到的内容当成事实写进画像，才算不通过。

### 2. 硬门槛

以下五项是硬门槛：

1. 分群轴位置不同；
2. 分群维度规则；
3. 行为关联业务目标；
4. 推导方向正确，不用设计倒推；
5. 来源可追溯。

其中"推导方向"只有通过和不通过两种结论，没有待补证。这一项只看论证方向，不看证据多少。

### 3. 不同阶段的结论上限

| 阶段 | 最高结论 |
|---|---|
| S1 | 结构合格，待验证 |
| S3 真实访谈 | 有证据支持，并写明边界 |
| S3 模拟访谈 | 只能判定内部一致，不能判为已证实 |

### 4. 闸门②的处理

- **有不通过项**：这个画像不能被选为主 Persona。修正后才能重新进入定选。
- **硬门槛项有待补证**：不拦下，但闸门②要逐条列出。每一条写明"如果这条不成立，会影响哪个判断"，由使用者选择补访，或者带着风险继续。AI 不替使用者放行，也不替使用者否决。
- **非硬门槛项有待补证**：写进研究缺口即可，不需要在闸门②逐条确认。

## 七、画像的写法

画像是把一类人写成一个具体的人，不是对受访者的归纳总结。读者要能一眼看出"他是谁、怎么做事、卡在哪里"。

### 1. 构成

| 部分 | 内容 |
|---|---|
| 头部 | 虚构姓名 + 角色（多角色产品）+ 与行为有关的基本信息（年级 / 年龄 / 身份），再加一句话 |
| 代表人群 | 一句话说明他代表哪一类人，用行为来定义，例如"家长陪学的低年级孩子：每天由家长叫来学，学的时候家长在旁边，读没读对由家长判断" |
| 正文 | 用户特点、用户行为、用户需求（目标层级）、用户痛点、典型场景、内在矛盾、否决约束（多角色产品）、关键差异 |
| 证据回指 | 统一放在画像末尾，正文里不挂编号 |

### 2. 规则

- **分群轴位置写成这个人的特点，放进「用户特点」。** 不用"轴1、轴2"做字段名。每一条分群轴上的位置，都必须能在「用户特点」里找到对应的一条，找不到就算缺失；或者说明这条轴已经不再用来区分。
  - 例：不写"轴1 启动：妈妈叫一次就开"，而写"启动靠家长：叫一次就来，不拖也不闹"。
- **姓名用虚构的**，不用受访者真实姓名。画像代表一类人，用真名会被当成某个人的描述，也有隐私问题。
- **基本信息可以写年级、年龄**，用于让读者认出这个人。这不违反分群规则：分群规则限制的是用人口属性分群或定选，不限制描述。
- **一句话要像这个人自然说出来的。** 优先摘一句原话；没有合适的原话时写成自述并标明。不能把两条记录拼接成一句。
- **正文不写研究过程。** 不出现"受访者""证据来自""记录显示"这类词，这些都放进末尾的证据回指。
- **末尾证据回指逐条写**，并标来源类型。例："用户特点② ← B-P09（家长转述）"。不能写"均为事实"。

## 八、动机分析（冰山）的写法

### 1. 动机的定义

动机是这个人为自己想要的东西，或者害怕失去的东西：一种愿望、一种担心，或者一种他看重的价值。主语必须是人，不能是产品或流程。

### 2. 下潜检验

每一层都要回答上一层的"为什么"：

- 理由回答"他为什么这么做"；
- 动机回答"这个理由为什么对他重要"。

动机一栏只是把理由换了个说法，就是没有下潜，要重写。

### 3. 不算动机的四类内容（出现即重写）

| 类型 | 例子 |
|---|---|
| 理由的复述 | "要的是'过关'，中间几遍不算数"；"亲耳听到才放心" |
| 产品机制 | "过程只要求跟着读到对，不要求自己想起来" |
| 心智模型 | "把 App 当判对错的裁判" |
| 需求或解法 | "要'没有提示也会'的证据"（这是 S4 需求池的内容） |

### 4. 自检句式

写出的动机要能套进下面这句话，并且读起来通顺：

> "他之所以【表层行为】，是因为他想要／害怕【动机】。"

改写示意（内容是推断，需要标明）：

- "亲耳听到才放心" → 怕孩子在自己看不到的地方糊弄过去，花了时间却白学。
- "要'没有提示也会'的证据" → 想确认钱和时间没有白花，孩子是真学会了。

### 5. 表格规则

- 第一列只放行为。痛点（例如"刚学完说不出词"）放在 S3 的卡点里，不放进这张表。
- 用户给出的理由是"没有问到"时，动机一栏不硬推，标「本轮未覆盖」。
- 表格有一列"谁"，标明是使用者、付费者还是守门人的动机。
- 动机要和画像里的目标层级一致。画像的 life goals 标了"本轮未覆盖"时，这里的动机只能标为推断，并写进研究缺口。由于 life goals 按需填写，动机也可能对应 experience goals，不固定对应 life goals。
