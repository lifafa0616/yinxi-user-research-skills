# S1 假设与 Persona 群

**这一步在做什么**：把产品背景和业务目标翻译成「我们认为用户是谁、他们实际怎么做事」的可验证假设。
**为什么必须现在做**：后面每一步都在修正这份假设。没有它，访谈无从设计，验证无从对照。

## 入口门禁

缺少以下任一项，不生成任何内容，只追问：

- **业务目标**（本阶段要提升什么，如转化 / 留存 / 完课 / 续费 / 客单价）
- **产品阶段**（0-1 验证 / 增长 / 成熟 / 转型）

追问一次问完，3-5 个问题一起列出，每个问题说明它为什么会影响产出。对可识别的产品名称、URL、应用商店页、竞品链接或产品描述，**先主动联网检索公开资料**；只追问公开渠道无法确认、但会影响研究方向的信息（业务目标、阶段、能否接触真实用户、未公开背景）。既有访谈、问卷、客服记录、后台数据等私有材料是可选补充，不作为入口必填。对使用者也不知道的信息（用户真实行为与动机）不要追问，直接标为假设并声明。

## 公开资料主动检索

当产品可识别时，在建立候选 Persona 前先检索公开可访问的信息，包括官网、应用商店页面、公开帮助文档、公开社媒内容、公开评论与第三方介绍。输出一段「公开资料速览」，写清：

- 产品公开定位、可见功能或服务机制、目标场景
- 公开用户反馈中反复出现的主题（若有）
- 每条信息的来源链接与类别：官方资料 / 公开用户反馈 / 第三方观点
- 公开资料无法回答、需要使用者确认的关键缺口

证据处理规则：官方资料说明产品自述；公开用户反馈说明个体公开表达；第三方资料只作背景。三者都不能代替真实访谈或内部数据，不能直接写成用户事实。对于使用者、付费/决策关系等，只能标「基于公开资料的推断」，请使用者确认或修正。

## 小节 0 输入回显

生成前先回显一段业务目标 → 研究对象的推导，让使用者确认：

> 你的业务目标是「X」，所以要研究的是【某类具体人群】；如果目标是「Y」，该研究的是【另一类人群】。这两批人的行为、痛点、动机完全不同。

多角色产品在此追问使用者与付费/决策者是否同一人，并回显主用户侧的推导。

同时声明证据状态：二手真实材料逐条标「事实」并列出来源；公开资料按「官方资料 / 公开用户反馈 / 第三方观点」单独标注；没有真实材料时，明确声明后续 Persona 与行为判断仍是待验证假设，不能把公开资料当作真实用户证据。

## 小节 1 分群依据说明（先于 Persona，三问必答）

1. **用了哪几条行为轴**（2-3 条），每条写出两端。例：`验收要求：要看到可信证据 ←→ 只要不出事就行`。轴超过 3 条时，交叉出的聚集点会多于 3 个，与「最多 3 类」的上限冲突，先砍掉与业务目标关系最弱的那条轴
2. **为什么是这几条**：每条说明它与业务目标的关系。与业务目标无关的轴不要用。
3. **为什么没用另一些轴**：显式点名被排除的人口属性轴（年龄、地域、性别、消费能力、职级等），逐条说明为什么它们在当前业务目标下不构成行为差异。

第 3 问是硬要求。只说「不按人口属性分群」时，人口属性会变成隐含轴偷偷回来。

## 小节 2 行为模式

表格输出：行为表现（标注 事实 / 推断 / 常识）| 可能原因（待验证）| 与业务目标的关系 | 是否值得验证

重点回答：哪些行为反复出现、哪些能解释痛点、哪些只是表面现象。

这一节同样不写设计启发或产品机会 —— 现在的任务是把行为看清楚，不是找机会。

## 小节 3 候选 Persona 群

2-3 个**平等的候选 Persona**，全部完整版、字段一致。**最多 3 类，这是硬上限。**

多角色产品中，另一侧（付费者 / 决策者 / 守门人）占用其中一个名额，不额外增加 —— 例如使用侧分出两类行为模式、再加一类付费或决策侧时，正好 3 类，不能再拆。

推导出 4 类以上时，合并行为轴位置最接近的两类，并写一行合并依据（合并了哪两类、依据哪条轴上的距离）。类别多不等于研究做得细：3 类以上时每类的访谈样本会摊薄到 1 位以下，任何一类都拿不到能校准的证据。

**此处不定主 Persona。** 主 Persona 必须从访谈证据中得出，S1 阶段没有任何数据，此时定主就是把一个猜测变成不可逆的前提 —— 后面的问题、校准、需求都会围着它转，访谈就只能验证「这个人存在吗」，而回答不了「到底该以谁为主」。主 Persona 在 S3 校准后的闸门② 定选。

**每个 Persona 的内容量以一页 PPT 为上限**：全部字段合计不超过 350 字，任何一条不超过 2 行。写不进一页的内容说明还没想清楚，不是内容太多。

这是内容量上限，不是排版要求。PPT 里一个 Persona 一页；报告里用表格排版，一页放两个。

| 字段 | 篇幅上限 | 要求 |
|-|-|-|
| 名字 + 一句自述 | 1 行 | S1 之前没有访谈，这句是**假设性自述**，标「假设」，不叫「原话」；只有手上有二手真实材料时才能引真实原话并标来源。要能体现心态，不写口号 |
| 角色标签 | 1 行 | 仅多角色产品：使用者 / 付费者 / 决策者 / 守门人 / 否决者 |
| 基本背景 | 1 行 | 只写与行为相关的项，不凑满人口学字段；不作为分群依据 |
| 行为轴位置 | 每轴 1 行 | 直接标在 S1 小节 1 定义的轴上（如「验收要求：偏『要看到证据』一端」） |
| 典型行为 | 2-3 条，各 1 行 | 具体可观察，标注 事实 / 推断 / 常识 |
| 核心痛点 | 2 条，各 1 行 | 未被满足的需求，不写解决方案 |
| **目标三层** | 各 1 行 | end goals 要完成什么 / experience goals 过程中想要的感受 / life goals 想成为什么样的人 |
| 关键场景 | 1-2 行 | 一个具体场景，不写一天的完整叙事 |
| 内在矛盾 | 1 行 | 必写，不许写成完美用户 |
| 与其他候选的关键差异 | 1-2 行 | 指向具体行为轴上的位置差，不以任何一个候选为基准 |

精简规则：

- 三条以内能说明的，不要写第四条。**典型行为写 2-3 条，痛点写 2 条**，多出来的进备注不进正文。
- 每条只留一个信息点，不要用逗号串起三个意思。
- 不写与行为无关的人口学装饰（星座、爱好、口头禅、通勤方式），除非它直接解释了某个行为。
- 深层动机不单独设字段 —— 它就是 life goals，重复写会让两处口径不一致。
- 场景写「上一次具体发生了什么」，不写「一天的生活」。日常叙事在这里不产生新判断。
- **本节不写设计启示、产品机会、功能建议。** 画像只描述这个人是谁、怎么做事。设计方向要经过核心任务流程、需求池、洞察、KANO 层层推导才能得出，在这里写等于跳过全部推导先给答案，后面的筛选会变成给它找理由。

多角色产品中，另一侧必须占用其中一个候选名额。

## 小节 4 研究缺口

指出哪些判断最缺证据、补什么材料能最快加固。这是 S2 访谈问题的主要来源。

其中必须包含一条：**目前无法判断哪个候选该为主，缺少的是各候选的真实行为证据。** 这条缺口由 S2 的访谈来填，是本轮访谈要回答的首要问题。

## 闸门① 访谈重点（可逆）

先读取入口已确定的证据路径。**能接触真实用户时走真实路径；无法接触时才走模拟路径。** 已选真实路径不得在此展示身份交接包、模拟对话或其说明；已选模拟路径才说明独立对话与交接包。除非学生主动要求改路径或先做模拟演练，否则不得再次提问或混合两路内容。

学生在此为**每个受访者组**确认本轮 20-30 分钟纯问答深访的研究重点；不决定谁先访谈，也不是主 Persona 判断。访谈重点是可逆的资源分配：信息不足时可以补访，主 Persona 仍只在 S3 闸门② 定选。

先说明每个受访者组都必须访谈，并给出建议：

- 每组提纲都包含：基础背景了解、使用习惯与最近一次经历、驱动因素、障碍因素，以及由业务目标与研究缺口定制的模块
- 建议只能依据**业务目标、研究缺口与客观角色关系**，不得以「行为证据强度」「产品价值」或主 Persona 倾向作依据——这些此刻没有证据支撑
- 每组通常 8-12 道主问题；追问按回答决定。控制在 20-30 分钟，优先保留最能支持本轮业务决策的问题

> **问题不是通用题库。** 每题必须服务于业务目标导出的研究目标或待验证假设；用户行为题可以不直接提产品，产品关联题则应依据最小产品背景和关键场景生成。不要用抽象的泛用题替代。
>
> **只有可比的对象才共用比较题。** 当两个候选属于同一受访者组、要回答同一个业务决策时，可为它们设计一组逐字相同、且与该组和产品背景强绑定的比较题。不同受访者组不得强行共用一套题；应按各组特性生成定制提纲，再围绕业务目标比较其影响。
>
> **覆盖风险**：20-30 分钟不能覆盖全部假设。未问到的判断在 S3 必须标为「本轮未覆盖」；若该组后来显示出关键问题，闸门② 前应补访。

优先用可点选卡片为每个受访者组单独选择研究重点，并写清对象：

- **优先验证哪些假设**：列出本轮最重要的 2-3 条假设及理由
- **优先了解哪些产品相关体验**：列出最关键的产品背景/场景及理由
- **我自己确定重点**：写明计划重点了解什么及理由

然后**停下**等使用者确认或改：使用者需说明每个组的访谈重点。不得自行通过。
