# S2 访谈方案

**这一步在做什么**：把 S1 里最不确定的判断，变成一份能直接拿去问人的方案。
**为什么必须现在做**：验证的对象是假设。假设没成型之前设计问题，只会问出泛泛的意见。

## 先锁定证据路径

在 S1 入口门禁中已回答「能否接触真实用户」；进入 S2 时直接沿用，**不得重复询问或混合输出**：

- **真实路径**：学生能接触真实用户。只生成真实访谈执行方案与记录模板，**不得输出、展示或提及《访谈身份交接包》**。
- **模拟路径**：学生不能接触真实用户。生成模拟访谈方案，并在文件末尾附每个候选的《访谈身份交接包》。

只有使用者明确要求改变路径或额外进行模拟演练时，才重新确认。

## 输出方式：创建 Markdown 文件

必须创建独立的 `访谈计划与提问清单.md`（同名已存在时加日期或版本号）。**不要把完整问题清单直接展示在对话框中**；对话中只给文件链接和不超过三条的执行摘要。

文件必须完整、可打印、可边访谈边记录，按以下顺序组织：业务目标回指与研究目标、证据路径/范围/样本、受访者分组、访谈前准备、每组独立提纲、收尾与记录模板；**仅模拟路径**再附身份交接包。

## 产出一 访谈计划

- 研究目标（回指业务目标，说明这轮访谈要支撑什么决策）
- **首要问题：产品应优先服务哪一类角色/候选，以及为什么。** 这是闸门② 定选的依据；问题清单必须能支撑这一判断，不能只验证某一个候选是否存在
- 要验证的假设清单（编号，来自 S1 小节 4 的研究缺口）
- 招募条件：只写行为筛选条件与核心场景
- 本流程不包含无障碍与包容性研究，属有意取舍；真实项目需另行补充（招募应覆盖不同能力的用户，设计方向需做无障碍检查）
- **样本量：每个候选各 1 位，合计 2-3 位**（等于 S1 的候选类别数）。每类都要访谈到，否则闸门② 定选时那一类只有假设、没有证据，等于没资格参与比较
- **时长与重点由学生在闸门① 分别确认**：每个受访者组进行一次 **20-30 分钟**的纯问答深访。提纲通常包含 8-12 道主问题和按回答决定是否使用的追问；问题由业务目标、产品背景、受访者组、场景和待验证假设推导，不能用固定题库凑数
- 模拟路径同样要跑这个数量。受访者是 AI 不构成减少类别的理由：少访一类，那一类在闸门② 就无法参与比较
- 记录要求：逐字记录，行为优先于态度
- 真实路径附加：知情同意、不要引导、多问「上一次实际是怎么做的」；若受访者组在授权/同意要求、语言能力、理解方式或可回答的信息范围上有特殊限制，访谈安排、问题语气、词汇、长度和记录方式必须相应调整
- 模拟路径附加：被访者只收到中性代号、基本背景、核心场景与逐题访谈说明，**不收到题目或题数**；完整问题清单只交给学生（见产出三）

题目生成前必须整理最小必要的**产品背景**：产品要解决什么问题、服务对象、核心价值或机制、用户关键场景、产品阶段与业务目标。若缺少会决定本轮研究方向的信息，先追问；**不得要求完整页面、流程、原型、账号或任务体系**，除非使用者主动提供并希望讨论。

## 产出二 《访谈计划与提问清单》（只交给学生）

**问题设计本身就是用研的核心能力，不是填模板。** 每道题都要能说出它验证 S1 里的哪条假设、为什么这样问才问得到。这份清单的质量直接决定后面全部推论的质量 —— 问错了，后面每一步都在认真处理错误的输入。

每个受访者组必须独立成章，按以下结构生成：

1. 本组访谈目的（回指业务目标与研究缺口）
2. 语言与访谈提醒（本组可观察范围、词汇、问题长度与表达方式；当语言能力、认知特点或授权要求不同，使用相应的沟通方式）
3. 开场白（介绍目的、无对错、可拒答或停止、记录许可；按该组的理解方式调整表达）
4. 基础背景了解（只问会影响分析的信息，从与场景相关的轻松问题开始）
5. 使用习惯与最近一次具体经历
6. 驱动因素与障碍因素
7. 由业务目标、产品背景和待验证假设定制的研究模块
8. 收尾话术（感谢、确认补充、说明后续处理，不承诺产品结果）

每题都必须回指**业务目标导出的研究目标或待验证假设**；写不出回指即删题或重写。优先问最近一次具体经历、动作、环境与后果；不用「喜不喜欢某功能」「重不重要」等抽象态度题。动机题必须锚定具体经历，追问只是备选指引，不规定次数。

问题分两类，缺一不可：

- **用户行为题**：了解用户原有习惯、真实场景、替代做法、决策方式或困难；可以不直接提产品，但必须说明它如何服务业务目标或哪条假设。
- **产品关联题**：围绕产品事实卡中的具体功能、页面、流程、内容材料、服务机制或待验证方案；用于了解用户是否会使用、如何理解、在哪卡住、是否支持业务目标。

整份提纲必须同时包含两类题，并有足够的产品关联题支持业务决策。若题目只停留在行业或品类层、无法关联任何产品背景，或整份提纲几乎没有产品关联题，判为不合格并重写。

问题表固定使用以下列：

| 编号 | 问题 | 类型（用户行为 / 产品关联） | 对应业务目标 | 验证假设 | 产品锚点（如适用） | 为什么这样问 | 可选追问 |
|-|-|-|-|-|-|-|-|

### 角色专属比较题（仅在可比时生成）

**不允许把所有候选强行塞进同一套 6 道题。** 不同受访者组必须生成各自的定制提纲；提纲应基于其角色、可观察的信息范围、使用/决策位置、语言能力、认知特点、关键场景和待验证假设设计，因此其语气、题目与可回答内容可以不同。

只有当候选属于**同一角色、需要回答同一个业务决策**时，才为这一组设计 4-6 道逐字相同的比较题。这些题仍必须绑定具体产品与场景，不能从通用题库套用。不同角色之间，以各自关键假设的证据、角色对业务目标的影响与记录中的具体行为作判断，不比较同一题、题数或回答条数。

### 角色/候选专属题

按这个候选的实际情况设计，数量与内容各候选可以完全不同。三处来源：

- 该候选在 S1 小节 4 里**独有的研究缺口**
- 该候选的**角色**决定了它能看到什么、不能决定什么（多角色产品尤其明显：守门人该问「你在什么情况下会不同意」，使用者该问「你上次卡在哪一步」）
- 该候选**核心场景里独有的动作与工具**

专属题**不参与横向比较**，在清单里标「专属」。它的作用是把这一类看清楚，不是和别人比高低。

每组提纲以 20-30 分钟为上限，通常为 8-12 道主问题；追问按现场回答决定，不作为必须完成的题目。基础背景、使用习惯、驱动因素与障碍因素必须出现，其余问题由业务目标、产品背景与假设定制；题目多不等于证据更强，后续不得按题数或回答条数决定重要性。

### 两层共同的要求

- 问题具体；避免引导性提问；不问「你喜不喜欢这个功能」；尽量问真实经历与行为
- **动机题挂在具体经历上直接问，不要留给追问去补。** 先锚定一件已发生的事，再问它的分量：「上次这么做的时候你最担心什么」「如果那次没做会怎样」「这件事对你意味着什么」。问得好可以一次拿到深层动机，S4 的动机分析就有引用可用，不必全靠推断
- 不要把动机写成态度题（「你为什么喜欢 X」「你觉得 X 重不重要」）—— 拿回来的是理由化的说法，不是动机
- 每题附一条**追问指引**（如「若回答停在行为层，可追问：上次这么做的时候你最担心什么」）。指引写给使用者自己用，不是写给 AI 的 —— 追不追问由他看着当场的回答质量决定，备好一句话而已，不要求每题都用
- **默认纯问答。** 不把选项、量表、分类标签或预设答案直接读给受访者；只有使用者明确要求排序、卡片分类等研究材料时才生成，并明确标「供访谈者/材料使用，不先读给受访者」。

## S2 完成后的步骤续接

首次创建或修订 `访谈计划与提问清单.md` 后，必须按 SKILL.md「修订后的状态续接」输出续接卡，当前状态一律是**S2 访谈方案 · 等待确认**。若本轮是修改，版本号递增，并说明本轮按反馈改了什么。

续接卡的下一步固定给使用者 2-3 个清晰动作：

1. 继续修改这份方案；
2. 确认这版并开始访谈；
3. 说明访谈执行上的实际限制，以便调整为可执行版本。

使用者确认后：

- 续接卡改为**S2 · 等待执行/回传**，按已选证据路径写清动作：真实路径按 Markdown 方案完成 20-30 分钟纯问答访谈并整理逐字记录；模拟路径按交接包和 Markdown 方案逐题完成独立访谈。
- 明确要求使用者将**每位受访者的一份完整记录**粘回主会话；收到并通过准入检查后，进入 **S3 校准**。

无论修改了几轮题目，均不得遗漏这张续接卡或把 S2 误判为完成。

## 产出三 《访谈身份交接包》（**仅模拟路径**，每个候选一份，不含题目）

产出二的完整问题清单是学生的访谈参考，不粘给被访者。**只有模拟路径**在 Markdown 文件中附每个候选一份完整、可整段复制的身份交接包；真实路径跳过本节，绝不展示空包、示例包或「如要模拟」说明。

份数 = S1 的候选类别数，一份对应一个对话。每份独立输出，不要合并成一段。

```
【本轮访谈身份】候选 A
基本背景：<年龄段 / 职业 / 家庭或组织结构 / 其他必要的客观信息>
核心场景：<你在什么情况下会遇到这件事，一到两句客观描述>

以下内容研究方刻意不提供，请不要索取，也不要反问：
行为 / 动机 / 痛点 / 期待 —— 全部由你从上面的背景与场景出发，按真实生活逻辑自行推导

接下来我会逐题访谈。你只回答当前收到的问题；你不知道后面会问什么，也不知道本轮共有几题。访谈结束时，我会明确通知你生成完整记录。
```

规则：

- **代号必须中性**（候选 A / B / C）。不给被访者 Persona 名称、行为轴位置、分类标签或任何带含义的称呼 —— 「高频使用者」这类名字本身就是假设，被访者会照着演
- **不把题目、题数或问题结构放进交接包。** 被访者预读题目会用前面的回答为后续问题铺垫，制造过于完整连贯的叙事；专属题还会泄露研究假设
- **不写「守门人」「否决者」等研究方判断。** 多角色关系只写客观处境，如「由一方实际使用，另一方负责付费或同意开始使用」；是否构成否决链由研究方在主会话依据记录判断
- 留空说明直接写进包里，是为了让使用者不会好心把假设补进去 —— 一旦补进去，被访者会复述假设，访谈变成自证
- **完整提问清单与追问指引只交给学生。** 学生依闸门① 选定的实际深度逐题发送；被访者只看到已经发出的当前问题

### 各候选靠什么区分（不能靠行为）

分群依据是行为轴，但行为不能给被访者。所以可区分性必须落在**背景与场景的客观差异**上：

- 客观处境差异：角色、职业、在组织里的位置、可支配时间、是否自己付钱、上一次接触这件事是什么时候
- 场景触发条件差异：什么情境下才会遇到这件事、由谁发起、结束后要交给谁

写法示例（行为轴是「验收要求：要看到可信证据 ←→ 只要不出事就行」）：不要写「他要求看到证据」，而写「他需要向别人交代这件事的结果」与「结果只有他自己看」。前者是行为假设，后者是客观处境 —— 处境不同，行为自然分化，而且分化是被访者自己推出来的，不是我们喂给他的。

**如果两个候选的背景与场景写完几乎一样，说明这两类本来就该合并。** 回 S1 合并，不要靠加行为提示强行区分。

对照候选的目的是**对比找出谁该为主**，不是「验证为什么这类不是核心用户」。后一种说法预设了答案，对照就没有意义了。

多角色产品中，另一侧用户占用其中一个候选名额，不额外增加。

## 交接与执行

- 模拟路径：**每个候选各开一个对话**（2-3 类就是 2-3 个对话），粘贴该候选的《访谈身份交接包》。学生参照 Markdown 文件逐题提问，不存在「AI 自问自答快跑」这个选项。
- 真实路径：学生只携带 Markdown 文件按访谈计划执行，带回逐字记录；不得生成或使用身份交接包。

**每个候选必须单独开一个对话。** 同一个对话里跑第二个候选，前一位的回答还在上下文里，第二位会不自觉地对齐或刻意区别于前一位，两份记录就不再各自独立 —— 而这两份记录恰恰是闸门② 定选的全部依据。

### 回传（这一步不能省）

访谈在别的对话里进行，主会话看不到。交接时必须把回传动作一起讲清楚。学生只有三个动作：

1. 模拟路径：新建对话并粘贴身份交接包；真实路径：按 Markdown 文件联络并访谈真实受访者
2. 按提纲逐题提问；模拟访谈结束时明确说「访谈结束，请输出本轮完整访谈记录」；真实访谈按约定整理逐字记录或转写
3. **把整份记录复制回主会话**（跑本流程的这个对话），一个候选一份

回传的记录是 S3 校准、闸门② 定选、报告附件三处的同一份来源。少一份，那一类在闸门② 就没资格参与比较，报告附件里也会缺一块。收到记录之后才做准入检查。

## 证据模式

证据路径在 S1 已选定并贯穿全流程；此处只按已选路径执行。混合来源仅在使用者明确要求时，按每条记录逐条标注。

## 准入检查（收到记录后，进入 S3 之前）

**每收到一个候选的记录就做一次准入检查**，不用等全部跑完。先返回的记录先检查，通过后再继续其余访谈。这样能尽早发现问题，不至于全部跑完才发现问题清单本身有毛病。

由本技能侧执行，不由被访者自评 —— 只有握有原始假设的一方才能判断记录里哪些信息超出了假设。

输出差异检测：

| 检查项 | 通过标准 | 不通过 |
|-|-|-|
| 新信息 | 记录中出现假设之外的行为、细节 | 全部落在假设内 |
| 行为具体度 | 回答含具体动作与顺序 | 大量态度化表达 |
| 矛盾点 | 出现与假设不一致的回答 | 毫无矛盾 |
| 差异记录 | 逐条列出「记录中有、假设中无」 | 未列出则补齐 |

- 模拟路径不通过：退回重访（调整问题、增加挑战性问题、加强行为优先约束）。
- 真实路径不通过：不退回，转为「下一位受访者要补问的点」。真实访谈的样本不可重跑。

追问是学生在访谈过程中根据回答质量自行决定的，不是流程检查项。记录里会如实写下本轮追问了几次，这个数字供 S3 判断动机层证据的厚度，但不作为退回条件 —— 追不追是学生的判断，不是 skill 的规则。

全部候选跑完后补一次横向检查：

- **每个候选是否都有记录？** 缺哪一类就说明该类在闸门② 无法参与比较，问使用者是补访还是接受「该类未验证」并在报告中标注
- 同一角色、同一业务决策下的比较题逐项覆盖情况列成小表（各候选 × 比较题，标 已答 / 未覆盖）；不同角色不强制同题比较
- 各组题数与追问次数另记一行，只说明覆盖范围，**不参与横向比较**（问得多的候选绝对条数天然更多，比条数等于比提问量）

## 补访（条件触发）

触发场景只有两个：准入检查的横向检查发现某候选缺记录；闸门② 前发现关键假设仍未覆盖、需要更多信息才能定选。除此之外不得补访。

**模拟路径补访：**

- 为同一候选新开一个对话，粘贴同一份《访谈身份交接包》（背景与场景不变），只问补访题目
- 补访记录的编号续接原编号（如原记录到 A-12，补访从 A-13 起），记录概况中标注「补访轮」
- 补访题目由主会话基于缺口生成，同样不进交接包

**真实路径补访：**

- 优先回访同一位受访者（背景一致，前后可比），编号续接原编号并标注「补访轮」
- 约不到同一位时，新找一位满足相同筛选条件的受访者，编号另起前缀（如 A2-01 起），报告附件注明这是该类的第二位受访者

补访记录与原记录在 S3 整理表中同等使用，引用时保留「补访轮」标识。
