# S3 校准

**这一步在做什么**：用回传的访谈记录校准候选 Persona，然后定出主 Persona，再画出它完成核心任务的流程。
**为什么必须现在做**：主 Persona 必须从记录里得出，这是第一次有外部输入的时刻；流程地图必须建在已定选的主 Persona 上，否则卡点是编的。

进入本步前必须已通过 S2 的准入检查。

**两条路的性质不同，措辞不能混：**

- **真实路径**：记录是用户事实。这一步叫**校准**，闸门② 定出的是**主 Persona**。
- **模拟路径**：记录是模型推演，不是用户事实。这一步叫**内部一致性校准** —— 检查 S1 的假设自己站不站得住、哪里是空的、哪里互相矛盾，同时训练提问与筛选。它不能证明用户真的这样。闸门② 定出的是**待验证的主 Persona 假设**，此后所有结论措辞一律带「待验证」，不得写成「已验证」「访谈证实」。

## 前置条件：记录已回传

**使用者必须先把各份访谈记录粘回本会话，才能开始 S3。** 访谈发生在别的对话里，这个会话看不到，凭上文推测记录内容等于跳过整个验证环节。

- 没收到记录：停下来向使用者要，说明缺哪个候选的
- 只收到一部分：可以先整理已收到的，但闸门② 之前必须补齐或明确接受「某类未验证」
- 记录是 S3 校准、闸门② 定选、S7 附件的共同来源，一份都不能靠推断补

## 小节 1 访谈记录整理表

| 验证假设（编号） | 记录引用 | 验证状态 | 对 Persona 的具体修改 |
|-|-|-|-|
| | 逐字引用，不改写，标记录编号 | 支持 / 需修正 / 被反驳 / 本轮未覆盖 | |

引用必须逐字，不要润色。润色过的引用在后面无法作为证据使用。

**四种状态里「本轮未覆盖」最容易被漏掉。** 每类只有 1 位受访者，且单次访谈时长有限，所以一定有假设本轮根本没被碰到。如实标成未覆盖，它就是下一轮访谈的输入；混进「不成立」里，画像会被砍掉本来可能真实的内容。

**每条引用标记录编号**（如 A-07、B-03，前缀是候选代号）。编号在访谈记录里已经唯一，不要再加行号。这个编号一路带到 S7 报告，作为结论旁的「←」引用来源；不标编号的话报告无法回指，也看不出一条结论来自哪一类用户。

证据模式为模拟时，这一列叫「模拟回答」，引用时标「模拟」，不叫「用户原话」。

## 小节 2 修正候选 Persona

- 输入：S1 的候选 Persona 群 + 上表
- 被访谈到的候选按记录校准；未被访谈到的候选保持原状并标注「本轮未验证」
- **内容量仍以一页为上限**：字段与篇幅上限沿用 S1 小节 3，合计不超过 350 字。校准是替换内容，不是追加内容 —— 有新证据就替掉旧描述，不要两条并存
- **按三种状态处理每条内容，只删被明确反驳的：**
  - 记录**支持** → 换成记录里的说法，标记录编号
  - 记录**反驳** → 删掉，并在候选对比表里记一笔（被反驳是有价值的结果，不是失败）
  - 本轮**未覆盖** → 保留，标回「假设（本轮未覆盖）」。没问到不等于不成立 —— 每类只有 1 位受访者、单次访谈时长有限，把未覆盖的内容一并删掉，等于用没做的访谈否掉了假设
- 保留并强化矛盾点：记录里出现的矛盾比假设里的矛盾更有价值
- 目标三层逐层更新，特别注意 experience goals —— 它最容易在访谈中被说漏，也最容易被 AI 补成套话
- 每个关键结论后标出整理表里对应的记录编号
- 证据模式为模拟时，本节标题为「候选模型」而非「修正版」

## 小节 3 候选对比（闸门② 的依据）

| 判断依据 | 候选 A | 候选 B | ... |
|-|-|-|-|
| 与业务目标的贴合度 | | | |
| **行为证据强度**（对该候选的关键假设：支持 / 反驳 / 未覆盖） | | | |
| 痛点严重度（记录中的具体表现） | | | |
| 可触达性 | | | |

这张表和 S1 闸门① 的区别在于「行为证据强度」这一行现在有内容了。S1 阶段这一格只能填「无数据」，所以那时不能定主。

### 填「行为证据强度」时，先判断对象能否比较

不同候选可能被问了不同数量的题；题数和证据条数天然偏向问得多的候选，不能作为重要性依据。命中率也不解决问题：各题覆盖面不同，不能用题数把不同角色、不同场景硬算成同一种证据。

因此按对象关系处理：

1. **同一角色、同一业务决策下的候选**：只比较为这一组预先设计的 4-6 道角色专属比较题，逐项标支持 / 反驳 / 本轮未覆盖；这些题可逐字相同。
2. **不同受访者组的候选**：不得比较谁答对了更多同一题。分别列出各自关键假设的证据，再以业务目标、该组对目标的影响、记录中的具体行为和痛点为依据作决策说明。
3. 每个候选的独有发现另列一行，只用来理解该组；题数与追问次数只说明覆盖范围，不作为比较指标。

其余规则：

- 在有限时长内出现、且能直接支撑关键假设的具体痛点，不因单次覆盖范围有限而自动降权
- 动机层证据按**来源**而非追问次数计入：用户自己说出的动机算引用证据（无论来自直接问动机的题还是追问），我们从行为推出来的标「推断」。追问次数为 0 不等于没有动机层证据
- **如果某候选的关键证据更突出、但覆盖范围不足，必须在推荐里明说**，并把「对该候选补一轮访谈再定选」列为选项（补访操作见 references/s2-访谈方案.md「补访」）。不要因为它证据条数少就默认另一候选胜出

同时必须报告：**访谈深度是否影响了当前判断的确定性。** 如果只问核心题的候选呈现出更严重的痛点或更符合业务目标的行为，直接说出来，并说明是否需要补访 —— 主 Persona 定选只能由记录得出，不受 S1 深度选择预设。

## 闸门② 主 Persona 定选

优先用可点选卡片给出选项（见 SKILL.md「向使用者提问与闸门的方式」）。给出推荐 + 上表 + 理由，然后**停下**等使用者确认或改。使用者需一句话说明为什么是它。不得自行通过。

**模拟路径下这个闸门定出的是「待验证的主 Persona 假设」**，不是主 Persona。选项措辞、结论措辞、报告措辞都要带上这一点 —— 模拟回答证明不了谁该为主，它只能说明哪个假设更自洽、哪里还是空的。

推荐时必须先回答一句：**这个推荐依据的是哪些与业务目标直接相关的记录，是否被题数或角色差异误导？** 若覆盖范围不足以支持定选，就说出来，并把「补一轮访谈再定」作为选项之一给使用者（补访操作见 references/s2-访谈方案.md「补访」）。

定选后：

- 主 Persona 进入 S4-S6 的主线
- 其余候选降为次 Persona，保留一页规模，作为对照与边界参考
- 若换人为主，明确指出这个反转来自哪几条记录 —— 这是本流程最有价值的产出之一
- 多角色产品：另一侧的候选无论是否为主，都保留其角色标签与否决约束

## 小节 4 核心任务流程地图

只为**定选后的主 Persona** 画一张。次 Persona 不画。

### 先确定这张图画的是哪条流程

**阶段必须从业务目标的核心任务里拆出来，不用通用漏斗。**

- 第一步：把业务目标翻译成一句「用户完成一次 ___ 的过程」。例：业务目标「提升有效学习任务完成率」→ 这张图画的是「用户完成一次有效学习任务」的过程
- 第二步：把这个过程拆成 4-6 个环节，环节名用用户的动作命名
- 每张图只画**一条**核心任务流程。业务目标涉及两条时（如既要完成任务又要续费），只画与主 Persona 最相关的那条，另一条留到下一轮

**禁止直接套用获客漏斗**（听说 → 了解 → 信任 → 试用 → 付费 / 触发 → 探索 → 决策 → 行动 → 反馈）。除非业务目标本身就是转化，否则漏斗阶段找出来的机会点全在转化环节，与核心任务无关，S4 的需求池会整体偏离业务目标。

命名不必叫「用户旅程」。叫「核心任务流程」「一次完整使用的过程」都可以，取决于这条流程实际是什么。

### 表格

每个环节五列：用户行为 | 用户想法 | 用户情绪 | 关键卡点 | 卡点对需求池的输入

- **卡点必须来自记录里具体的行为描述**，逐个标注记录编号；找不到来源的卡点删掉。模拟路径下这些卡点同样标「模拟」，是待验证的卡点假设
- 卡点是 S4 需求池的主要输入，宁少勿凑
- 最后一列只写「这个卡点指向什么待解决的问题」，不写功能建议或设计方向 —— 那些要经过 S4-S5 推导才能得出
- 开头写明这张图画的是哪条流程、为什么是它（回指业务目标）

## 真实路径提示

真实用户的回答比模拟访谈散乱、跑题、信息密度低，整理出来的表格看起来会比模拟"难看"得多，空白和「不确定」会更多。这是正常的，不代表做错了 —— 模拟访谈的整洁来自 AI 的推理能力，不来自用户。

不要因此退回去做模拟，也不要用推断填满真实路径的空白。空白本身是有效信息，它指向下一位受访者要补问的点。
