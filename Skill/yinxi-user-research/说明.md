# yinxi-user-research · 用户研究工作流 Skill 包

> 两个 Skill 协同工作，让学生独立跑完一条完整的用户研究流程：做研究 → 输出用户画像 → 输出设计方向。

## 包内 Skill

| Skill | 角色 | 目录 |
|-|-|-|
| `yinxi-user-research-loop` | 主流程（S1-S7 + 3 闸门 + 回传） | `./yinxi-user-research-loop/` |
| `yinxi-user-research-interview` | 被访者（独立对话防自证） | `./yinxi-user-research-interview/` |

**为什么分两个 Skill**：防自证。同一个对话里既做研究又扮演用户，模型会复述自己的假设。独立对话让被访者只拿到中性代号 + 背景 + 场景，看不到任何行为 / 动机 / 痛点假设。

## 功能

从业务目标出发，依次产出：候选 Persona 群 → 访谈方案 → 校准模型与核心任务流程地图 → 需求池 → 候选功能与 KANO 筛选 → 设计方向，最终自动汇总为一份 10 页左右的《AI 辅助用户研究与设计决策报告》。

## 适用场景

- 集创堂 / 银溪课程的用研作业
- 需要从业务目标推导到设计方向的完整用户研究
- 需要生成 Persona 并经访谈校准后定选主 Persona
- 模拟访谈演练（AI 扮演被访者，学生亲自提问）

## 两个副本

| 用途 | 路径 |
|-|-|
| **活跃副本**（Factory 实际加载的） | `~/.factory/skills/yinxi-user-research-loop/` 和 `~/.factory/skills/yinxi-user-research-interview/` |
| **仓库副本**（版本管理、交接、阅读） | `SilverAI/Skill/yinxi-user-research/`（本目录） |

**改规则时改活跃副本，然后同步到仓库副本。** 两个副本内容应保持一致；如果不一致，以活跃副本为准。

## 项目文档

设计决策、审查记录、当前状态与待办在 `SilverAI/Project/用户研究工作流/` 下：

- `HANDOFF.md` — 架构决策、两轮审查修复清单、关键决策记录、当前状态
- `当前阶段产出.md` — 关键规则速查表
- `README.md` — 项目地图

## 教学设计原则

核心矛盾：Skill 提供便捷，但"一键输出"会让学生跳过理解。设计原则是**有界选择而非无界编辑** —— 闸门处给学生选项让他选，而不是让他在 AI 的长篇输出上自由编辑。前者学到东西，后者学不到。
